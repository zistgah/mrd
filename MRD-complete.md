## How to read the provenance class on every entry

This document distinguishes four things that are routinely collapsed:

| | |
|---|---|
| **`[RETRIEVED]`** | corroborated in the durable record or a live repository |
| **`[PARTIAL]`** | named and partly recorded; the definition is incomplete |
| **`[SYNTHESIS]`** | present only in a prior assistant's synthesis. **Not evidence.** |
| **`[UNRESOLVED]`** | the record does not contain it, and nothing has been substituted |

**Why this matters more than it sounds.** A failure mode was identified in this work and named:
an assistant reconstructs the estate, that reconstruction becomes a poster, the poster is later
read back as a source, and a new synthesis is built on it. Recursive self-sourcing. So:

> retrieved fact ≠ prior assistant synthesis ≠ poster-derived inference ≠ unresolved item

Everything below marked `[SYNTHESIS]` came to me through another assistant's summary and I could
not corroborate it independently. It is recorded because it is probably right and definitely
useful — and marked because probably-right is not the same as retrieved.

### The four epistemic rules that govern this document

- **Retrieval Before Assumption**
- **Read Before Write**
- **Verify Before Claim**
- **Preserve Before Transformation**

An unresolved entity is allowed to remain unresolved. Missing information must not be filled by
symmetry, by analogy, or by aesthetic completion.

## The four publication layers, in order


| | system | asserts | denies |
